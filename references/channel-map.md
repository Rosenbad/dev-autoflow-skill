# 本环境开发通道速查（Phase 2 必读）

豆包环境内的开发能力是**一组有明确分工边界和红线**的通道。路由的关键不是"会不会"，而是**该不该用某个通道**。下表浓缩了各通道的边界与红线——这些细节模型不会自动知道，误用会导致产物错误或返工。

## 通道一：本地代码执行（MainAgent 直接开发）

适用：脚本、工具、单文件程序、数据处理、本地 HTML/CSS/JS 单页。

**红线**：
- 本机 shell 是 **PowerShell 7.6**（pwsh），Bash 工具被禁用——所有命令走 PowerShell 工具。
- 涉及文件搜索用 Glob/Grep，内容读写用 Read/Write/Edit，不要用 shell 的 find/grep/cat 替代。
- 新建文件前先 `ls` 父目录；路径含空格必须加引号。

## 通道二：HTML 单页 / 可视化

适用：官网、落地页、数据看板、可视化报告、信息图、动画、游戏、3D、静态展示型页面。

**判定红线**：
- **静态展示** → html 通道；**需要交互/工具型/数据会更新** → webapp（app-builder）。
- 用户说"做个网站/应用/平台"≠必须 webapp。判据是**实现上需不需要工程**（npm 依赖、dev server、复杂跨页状态），不是产品叫什么。
- **产物素材一律用本地文件 + 相对路径**，禁止平台 CDN 链接（会失效/防盗链）。代码依赖除外。

## 通道三：网页应用（app-builder）

适用：多页面/全栈应用、数据看板工具、表单/预约/收集、登录权限、数据库、后端 API、需要运行时调用 AI 能力的产品。

**判定红线**：
- 需要服务端能力或运行时 AI 生成 → `app_builder_agent`（jspage/fullstack）。
- 产物在 app-builder 沙箱中，MainAgent 不持有源码——用户要发布时按 jspage（自动发布）/fullstack（用户手动发布）答复。
- 单页 HTML 和 H5 **不要**走 app-builder。

## 通道四：表格 / 数据

适用：Excel/CSV/XLSX、飞书表格、数据分析、财务建模。

**红线**：
- 任何表格任务**第一个工具调用必须读 `sheet/SKILL.md`**。
- 数据分析归因类走 `doubao-data-analysis`；纯表格读写美化走 `sheet`。

## 通道五：文档 / 汇报

- Word/党政公文/合同 → `word` / `doubao-contract-drafting`。
- 飞书文档/在线文档 → `lark-doc`；PPT → `ppt`；PDF → `pdf`。
- **注意**：PDF 或非 DOCX 文件不要因为"长度规则"就转成 Word。

## 通道六：创意 / 多媒体

- 图片生成/编辑 → `doubao-creative-design`（必须先完整走设计交付流程）。
- 视频生成/编辑 → `doubao-creative-video` / `seedance-25`（短剧用 `doubao-creative-drama`）。
- 音视频处理 → `byted-mediakit-*`。

## 通道七：委派 OrganizeAgent（多通道/大规模）

适用：多通道研究（多渠道、多平台、多场景对比）、重复独立流水线、资源密集处理。

**注意**：委派阈值规则在系统委派章节中已定义，**不要在此重复推演**——直接按系统规则判定。本条只提示信号词：
- 用户要求"深度调研/全面比较/系统分析"多个对象或多个渠道
- 任务含大量独立单元（每条都要"获取→处理→验证"）
- 单语料巨大（数十万记录/GB 级）

**红线**：小任务、单通道任务不委派——委派有固定启动与同步开销，是纯浪费。

## 通用铁律（全部通道适用）

1. **能直接做的不委派；能用一个 skill 的不开多通道**——多 skill 串行放大上下文成本。
2. **一次问清，不超过 3 问**——能合理假设的低影响项直接采用并写入【待确认项】。
3. **规格未定稿前禁止开工**；需求模糊依赖实时信息时，先探查再定稿。
4. **交付前验证**：代码跑测试/真实入口；网页渲染检查；表格重算关键指标；文档检查结构与来源一致性。
